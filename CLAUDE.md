# Notionix

Clone local de Notion, réimplémentation originale (ne jamais copier de code ou d'assets Notion). Voir README.md pour l'état et les TODO.

## Architecture

- `src/shared/types.ts` : contrat `NotionixApi` partagé main/preload/renderer.
- `src/core/` : code sans Electron partagé par l'app de bureau et le serveur. `db/` : `database.ts` (migrations via `PRAGMA user_version`, `openDatabase(fichier)`), `pageRepository.ts` (toute la logique pages/arbre/corbeille/recherche), `text.ts` (texte pour FTS).
- `src/core/transfer/` : import d'export Notion (`sources.ts` zip/dossier/zips imbriqués, `notionImport.ts` plan d'arbre + insertion, `markdownToDoc.ts` markdown-it vers JSON ProseMirror, `canonicalDoc.ts` validation contre le schéma réel) et export (`docToMarkdown.ts`, `markdownExport.ts`).
- `src/shared/editorExtensions.ts` : schéma de document partagé éditeur/importeur (imports TipTap nommés : les imports par défaut cassent le build main).
- `src/core/assets.ts` : images stockées par empreinte (`userData/assets/<sha256>.<ext>`), servies par le protocole `notionix-asset://file/<nom>` (nom validé, jamais de chemin libre). Les importeurs reçoivent l'`AssetStore`.
- Blocs ajoutés en phase 2 dans `editorExtensions.ts` : Image, TableKit, Details (toggle), `callout.ts`. Vues interactives côté renderer seulement (`CalloutView.tsx`), poignée de blocs maison (`blockHandle.ts`, sans Yjs).
- Bases de données : `src/shared/database.ts` (types, `parseSchema`/`normalizeValue` à la frontière, filtres, tris, regroupement, conversions, parsing FR/EN des nombres et dates ; logique pure partagée main/renderer), `src/core/db/databaseRepository.ts` (base = page `kind='database'` + `db_schema` ; lignes = pages enfants + `properties`), `src/renderer/src/database/` (vues, cellules, menus). Bases Notion : `transfer/csv.ts`, `transfer/notionDatabase.ts` (inférence des types) ; CSV écrit par `markdownExport.ts`.
- `src/main/ipc.ts` + `src/preload/index.ts` : canaux `pages:*` et `transfer:*` (dialogues natifs côté main), sandbox + contextIsolation.
- `src/renderer/src/` : `store.ts` (Zustand), `components/`, `editor/` (TipTap + menu `/`).
- Persistance : `node:sqlite` (pas de module natif). Tests unitaires sous Node 24 (`.nvmrc`), e2e Electron dans `tests/e2e/smoke.mjs`.
- Serveur (`server/src/`, construit par `npm run build:server` en `out/server/main.mjs`, mêmes dépendances que l'app, plus de package séparé) : `workspace.ts` (même `PageRepository`/`DatabaseRepository`/`AssetStore` sur `workspace.db`), `rpc.ts` (opérations de `NotionixApi` autorisées, arguments vérifiés, rôle `reader` en lecture ; le contenu des pages n'est PAS modifiable par RPC), `collab.ts` (un document Yjs par page `page:<id>`, initialisé depuis le contenu SQLite puis réécrit en JSON dans `workspace.db` à chaque stockage ; canal `workspace:main` en lecture seule qui annonce les changements), `api.ts` (cookie de session `HttpOnly` + en-tête `X-Notionix-Client: web` obligatoire pour toute modification par cookie, import zip, export, images), `static.ts` (client web + CSP). Noms partagés dans `src/shared/collab.ts`.
- Client web (`src/web/`, `npm run build:web` en `out/server/web`) : réutilise tout `src/renderer/src` ; `api.ts` implémente `NotionixApi` par `/api/rpc`, `session.ts` (Hocuspocus, une seule WebSocket `/collab`, Collaboration + CollaborationCaret), `main.tsx` installe `window.api` et `setPlatform` avant de charger l'app. Le renderer ne connaît le web que par `src/renderer/src/platform.ts` (`session`, `imageSrc`, `canEdit`) : pas d'import Yjs dans l'app de bureau. Images : src stockée `notionix-asset://…`, affichée `/api/assets/<nom>` via `imageSrc`.

## Branding

Logos générés par `scripts/build-logos.py` depuis `branding/notionix-brand-sheet.png` ; ne pas éditer à la main les PNG de `src/renderer/src/assets/logo-*` ni `build/icon.*`. Composant `components/Logo.tsx` (`<picture>` clair/sombre).

## Conventions

- Ajouter une migration = nouvelle entrée dans `MIGRATIONS` ; ne jamais modifier les anciennes.
- Toute écriture incrémente `version` et `updated_at` (prépare la sync).
- Import Notion : tester tout changement sur un vrai export avec `npm run build && node scripts/import-check.mjs export.zip` (profil jetable, rapport, arborescence, schémas). Formats réels observés : dossiers de sous-pages sans identifiant, liens encodés (`%20` avant l'id), modèles de base = pages sans ligne CSV, `- [ ]  ` pour une tâche vide, `-` seul pour un élément vide, équations `$…$`/`$$…$$`.
- Tests e2e : lancer Electron avec `CHROMIUM_FLAGS` (`tests/e2e/flags.mjs`), sinon les fenêtres en arrière-plan rendent les tests instables.
- Le contenu d'une page n'est jamais modifiable par RPC (seulement `pages.createWith` à la création) : sur le serveur il appartient au document Yjs.
- Vérifier avant commit : `npm run typecheck && npm run lint && npm test && npm run test:e2e` (l'e2e attrape les problèmes de bundling main que vitest ne voit pas). Serveur : `npm test` couvre `server/test/` ; image : `docker build -f server/Dockerfile -t notionix-server .` (contexte = racine).
- Équipe : `src/core/access.ts` (niveau d'une personne sur chaque page : accès 'inherit'/'workspace'/'restricted' + partages, rôles admin/editor/reader/guest ; seule source de vérité des droits, utilisée par `server/src/rpc.ts` (`CallContext.need`) et `collab.ts`). `src/core/db/teamRepository.ts` (commentaires, notifications, activité, rappels). Historique dans `PageRepository` (`recordVersion`, fenêtre de 10 min). `PageRepository.actor` = auteur des écritures (`as()` côté serveur, 'local' sur le bureau).
- Blocs : `src/shared/blocks.ts` (colonnes, TOC, lien de page, fichier, vidéo/audio, bloc synchronisé = page cachée `kind='synced'`, bouton, titres repliables), `src/shared/mention.ts` (mention + marque commentaire), `src/shared/colors.ts` ; vues React dans `src/renderer/src/editor/blockViews.tsx` passées par `createDocumentExtensions(..., { views })`. Toute nouvelle node doit être dans le schéma partagé (le serveur convertit Yjs ↔ JSON avec).
- Bases : nouveaux types dans `shared/database.ts` (person, files, status, created_by, last_edited_by, unique_id), `mergeSchema` (fusion à trois), relations synchronisées et sous-éléments dans `DatabaseRepository` (`syncRelation`, `enableNesting`), vues `TimelineView`/`ChartView`/`FormView`, vues liées = attribut `views` du nœud `databaseView`.
- Feedback (serveur seulement) : table `feedback` de `notionix-server.db`, `server/src/feedback.ts`, routes `/api/feedback`, fenêtre `src/web/FeedbackDialog.tsx` (passée au renderer par `ServerSession.Feedback`), notifications de type 'feedback' (ref = id du retour).
- Web seulement : `src/web/PublicView.tsx` (pages publiées `/p/<lien>`, `server/src/publicPages.ts`), jetons d'API (`auth.ts`, préfixe `nxk_`, doc `docs/api.md`).
- Une seule copie de `yjs` (racine) : ne pas réintroduire de `node_modules` sous `server/`, sinon Yjs est chargé deux fois.
- Formules et rollups : `src/shared/formula.ts` (analyse + évaluation sans eval), `src/shared/computed.ts` (calcul à la lecture dans `DatabaseRepository.get`, jamais stocké : `normalizeAll` avant chaque écriture).
- `Popover` enregistre ses écouteurs une seule fois, dès le montage (ref vers le dernier `onClose`, événements antérieurs à l'ouverture ignorés par `timeStamp` ; pas de `setTimeout`, sinon un Échap juste après l'ouverture est perdu) ; ne pas mettre `user-select: none` sur un élément `draggable` (Chromium n'y démarre pas le glisser).
- Plusieurs espaces (serveur) : `server/src/workspaces.ts` (registre ; `main` = `workspace.db` + `assets/` à la racine des données, ouvert à tous ; autres dans `workspaces/<id>/`, membres + admins), choisi par requête via l'en-tête `X-Notionix-Workspace` (`WORKSPACE_HEADER`, client : `src/web/workspace.ts` + `http.ts`). Collab : l'espace d'une page est retrouvé par son id (`Workspaces.findPage`) ; avis `changed` portent `workspace`. Images GET : cherchées dans les espaces de la personne (un `<img>` n'envoie pas d'en-tête).
- Groupes (serveur) : `server/src/groups.ts`, tables `groups`/`group_members` de `notionix-server.db` ; un partage vers un groupe = `page_shares.user_id` = id du groupe (`grp_…`) ; `User.groups` → `Viewer.groups` dans `resolveLevels`. Suppression d'un groupe : `PageRepository.removeShareTarget` dans chaque espace.
- Imports d'autres outils : `src/renderer/src/importers/documents.ts` (côté client, desktop et web : .docx via mammoth chargé à la demande, HTML/Markdown/texte, .enex avec `md5.ts`, zip Confluence/Google Docs) → HTML analysé inertement puis lu par le `DOMParser` ProseMirror du schéma partagé → `pages.createWith`. Pièces jointes → `assets.saveFile` + `div[data-type=file]`. Ids réservés à l'avance (`PageInit.id`, UUID ; `pages.createWith` refuse un id déjà utilisé dans n'importe quel espace via `ServerScope.pageIdFree`).
- Boîte de réception multi-espaces : `inbox.list`/`inbox.markRead` parcourent `ServerScope.others` (items marqués `workspace`) ; liens d'un autre espace : `GET /api/locate/<pageId>` puis `workspaces.switchTo(id, pageId)` (store : `openElsewhere`, discussion à rouvrir via `pendComments`).
- Statistiques de vues : table `page_views` (`recordView` : une vue par personne et demi-heure, `stats`), appelée par `App.tsx` à chaque changement de page. Recherche filtrée : `PageRepository.search(q, limit, SearchFilters)`.
- Toujours lire `properties`/`db_schema` via `parseRowProperties`/`parseSchema`.
- Pages importées : colonne `source` unique (`notion:<id>`, `notion-folder:<chemin>`) ; ne jamais écraser une page déjà importée.
- Commits de ce repo : auteur `bouzoubad` (config git locale), sans ligne Co-Authored-By.
